# KPI App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mobile-first Lao KPI evaluation app (forms ①–④, KPI approval chain, auto scoring A–E) for ~90 staff, backed by Google Sheets.

**Architecture:** One pure server module (`src/server.js`) holds all business rules and permissions over an abstract store; it runs in Apps Script (Sheets store), in the browser (localStorage store = demo mode) and in Node tests (memory store). `src/scoring.js` is shared by server and UI. `build.js` concatenates sources into `dist/index.html` (GitHub Pages) and `dist/Code.gs`.

**Tech Stack:** Vanilla JS (ES2019, no deps), Google Apps Script V8, Node 24 for build + `node:assert` tests, Phetsarath OT embedded base64 (copied from `Internal Audit App/src/fonts`).

**Spec:** `KPI App/docs/2026-11-05-kpi-app-design.md`

## Global Constraints

- UI text Lao only; font Phetsarath OT; works at 360px width; tap targets ≥ 44px.
- GAS `/exec` URL never in source: set via setup screen or `?api=` param, stored in localStorage `kpi_api`.
- All permission checks in `server.js`; per-evaluator ③④ answers never leave the server for non-HR users.
- Weights per group sum to 100; section-I item weights must sum to the group's I weight before submit.
- Grade from total rounded to 1 decimal: A ≥95, B ≥85, C ≥75, D ≥65, else E.
- No push/deploy to GitHub or Google without the owner asking.

## Review Focus

1. Evaluatee whose peers/subordinates submit nothing → section II weight redistributes, total still ≤ 100 (test in Task 1).
2. Only one peer/subordinate submitted → non-HR view shows "ຂໍ້ມູນໜ້ອຍເກີນໄປ", not the number (test in Task 2).
3. Supervisor changes mid-round (HR edits `sup`) → duties follow the new supervisor; already-submitted answers stay (test in Task 2).
4. Double submit (slow network, user taps twice) → second `answerSubmit` rejected, no duplicate row (test in Task 2).
5. Float boundary 94.95 → 95.0 → A (test in Task 1).

### Task 2: Server rules (pure)

**Files:** Create `src/server.js`, `tests/server.test.js`, `tests/helpers.js` (memory store + seed)

**Interfaces — Consumes:** Task 1. **Produces:**
- Store contract: `store.load() → {staff:[],rounds:[],kpi:[],peers:[],answers:[],sessions:[],config:obj|null}`; `store.save(db, changedTables:string[])`; `store.hash(s) → hex string`; `store.now() → ms`; `store.lock(fn)`.
- `handle(req, store) → {ok:true, ...} | {ok:false, err:'Lao message'}`; `req = {a, t, ...}`.
- Actions: `login{code,pin}`, `logout`, `boot`, `kpiSave{emp,items}`, `kpiSubmit{emp}`, `kpiAck{ok,msg}`, `kpiHr{emp,ok,msg}`, `kpiAppr{emp,ok,msg}`, `kpiPres{emps,ok,msg}`, `kpiUnlock{emp}`, `answerSubmit{form,emp,ans}`, `answerReopen{id}`, `staffSave{row}`, `staffImport{rows}`, `setPin{code,pin}`, `roundCreate{name,copyKpi}`, `roundStatus{id,status}`, `peerSet{emp,peers}`, `configSave{config}`.
- KPI status: `draft→ack→hr→appr→pres→ok`; return (ok:false) needs msg, goes to `draft`; `approverOf(e)= e.appr || sup(sup(e)) || null` (null → hr goes straight to `pres`; no PRESIDENT in staff → `pres` goes to `ok`).
- Round status: `setup|eval|closed|published`; one non-closed/published round at a time.
- `boot` returns `{me, staff(dir), config, rounds, round, kpi, duties, answersMine, results, hr?}` filtered per spec §4/§5; `duties` = list of `{kind:'kpiSet'|'kpiAck'|'kpiHr'|'kpiAppr'|'kpiPres'|'f1'|'f2'|'f3'|'f4', emp, done}`.
- Results: non-HR gets parts with `peer/sub = null, few:true` when n==1; employee sees own only when `published`; supervisor sees direct subs when `published`; HR always (live).
- Login lock: 5 fails → `lockUntil = now+15min`; session ttl 30 days; staff row never returned with `pin`.

  - login wrong pin ×5 → locked; right pin → token; `boot` without token → error.
  - full KPI chain sup→ack→HR→appr→pres(bulk)→ok; weight sum ≠ I weight → kpiSubmit error; non-supervisor kpiSave → error; return without msg → error.
  - `answerSubmit` f1 before KPI ok → error; in `setup` round → error; twice → second error; f3 by non-assigned → error; f4 for SPEC leader target → error; missing answer → error.
  - peerSet rejects self/sup/direct sub.
  - SPEC employee boot never contains another person's f3 answer rows; HEAD with 1 subordinate answer → `results.parts.sub===null, few:true` for supervisor view after publish, number present for HR.
  - HR changes `sup` of an employee → new sup gets f1/f2 duties, old sup doesn't; previous submitted answer kept.
  - `roundStatus` closed → results computed; employee sees result only after `published`.
